# Literate scripts without a notebook runtime (`mini.lit`)

A report needs four things: prose and Python side by side, Markdown and code cells, HTML output in our own styles, and fast re-renders (cached computation, tens of milliseconds while editing and under a second from a fresh process). It does not need cells that run out of order, a browser-side editor, or a runtime the page loads from a CDN. Our reports use a thin slice of Marimo's API (`mo.md` and `mo.stop`, over a few thousand lines of helpers), and much of the tooling around them (`report.css`, `md.css`, `clean_marimo_md.py`, `export_report_md.py`, the offline render skill) exists to bridge the rest.

`mini.lit` is the prototype: a plain Python file (a *literate script*) whose top-level string literals are prose and whose code between them is a cell, prose that quotes a value written as an f-string and evaluated field by field against the cells' namespace, the same pymdownx Markdown dialect as `mo.md`, a `@memo` cache keyed by `mini.memo`'s source and input fingerprints, `stop()` with pending marks for a preregistration, a watch-and-reload server, and Markdown, HTML and PDF outputs from one pass. Demos in `docs/lit/`; `./go lit render|serve`.

Open, in rough order:

- ~~Settle on one spelling.~~ Done: the Python form, since a plain `.py` gets ruff, ty, and go-to-definition for nothing (ty already caught a `None` subscript in the demo), and the Markdown parser is gone. `# %%` markers were tried as cell boundaries and dropped: prose already delimits cells, and a debugger covers what "Run Cell" would. Per-cell code visibility went with them; no report has ever shown its code, so hidden is the default and `# code: show` is for a page about the code. A first-line comment directive is the way back if a mixed page turns up.
- Port one real report (an sca2 experiment) and time it end to end, with figures through `@memo`. The prototype's numbers are from the two demos only.
- Publishing: the woven output is already a bundle (`index.html` + `_assets/`), so `./go publish` and `build_site` should accept a lit document beside a notebook export, and give it the same banner (`mini.reports.set_banner`: the index link and the link back to the source on GitHub) every published report carries at the top. The site build currently skips any `.md` under `docs/` that contains a cell.
- Markdown output: figures come through as the `<figure>` HTML `themed` emits; the `report-render` skill wanted `![alt](path)`, so `themed` should take a plain-Markdown target.
- `--pdf` needs a Chromium, and the devcontainer image has none: `sudo apt-get install chromium` (about 200 MB) works on it today, and `mini.lit.render` also finds `$CHROMIUM` or a `playwright install` download. If PDFs become routine, put the package in `post-create.sh` (Codespaces storage is the cost) and give the print stylesheet a page size.
- A theme toggle on the page (the figures and swatches already honour `body[data-theme]`), self-hosted fonts, and a table-of-contents option.
- The cache is project-wide and keyed by function name and inputs, so two documents defining a same-named cell function with the same inputs share a key and thrash the on-disk record (never serving each other's value, since the source fingerprint differs). Key by document as well if that turns up.

## Notes

**2026-09-18, Fable (with Sandy)** — Ported one real report: sca2's ex-2.1.12 (475 lines of Marimo; four cells, five figures, an HTML table, admonitions, footnotes, a `stop()` guard), by hand in about an hour. Prose paragraphs came out identical to `./go render`'s, numbers included, and the ten PNGs byte-identical to the Marimo export's. Timings on the cloud sandbox: cold fresh process 10.0 s against 25.5 s for the Marimo bundle export (with its PDF), warm fresh process 4.7 s (all of it the store's `get_refs` over the network plus 0.8 s of imports; the figures were memo hits), same-process re-render with nothing changed 20 ms, PDF +1 s. Two things the port surfaced: a docstring under a constant is top-level prose (wants a lint), and the woven `index.md` carries each figure's `<style>` block, which is the plain-Markdown target item above. The format question is settled by the port: the `.py` spelling carried it, so the `.md` parser can go. Findings and the publishing seam are in sca2's `todo/eng/literate-reports.md`.

**2026-09-18, Fable (later)** — Prose can now be an f-string: a top-level `rf"""…{x:.2f}…"""` is evaluated field by field in the namespace (a plain string stays a Jinja template), and past a `stop()` each field that fails renders as a pending mark with its source as the label. The point is that the names in prose become real references, so ruff, ty, vulture, and go-to-definition all see them; in the sca2 trial that cleared 21 vulture findings and reads closer to the `mo.md(f"…")` it replaces. Also `is_literate_document(path)` (a `.py` with a `# title:` header), which sca2's publish check uses to tell a literate document beside a Marimo report from one of the report's inputs. Worth deciding whether Jinja stays at all once documents are f-string-first: `{% for %}` tables are its remaining case, and a helper returning HTML covers that.

**2026-09-18, Fable (evening)** — Settled with Sandy: the term is *literate script*, and Jinja is out. Prose is a plain string (static, shown as written) or an f-string (evaluated field by field), and the Markdown spelling went with the templates, since without interpolation it was Markdown with display-only fences. The per-field pending marks past a `stop()` never depended on Jinja, so a preregistration still reads whole, and each mark now carries the field's source (`summary.m_line`) rather than the root name. What went with `{% for %}`: a table's rows are a comprehension in one field (see the tour), and a helper returning HTML covers anything larger. Two things the switch surfaced: a paragraph of math stays a plain raw string (an f-string would read `\frac{1}{n}` as a field), so a paragraph that needs both math and a value doubles its math braces; and the first cell used to start at line 1, so `# code: show` was shown as code. `is_literate_document` became `is_literate_script`. `jinja2` stays a dependency for `mini.temporal.dopesheet`.

**2026-09-18, Sonnet (docs cleanup)** — Marimo has now been removed from this repo entirely: the package and its dependents (`./go open`, `./go annotations`, `scripts/clean_docs.py`, `scripts/clean_marimo_md.py`, `scripts/edit_notebook.py`, `bin/marimo`, the marimo-format hook, and the Marimo branches of the export/render/site scripts and of `src/mini/reports.py`) are gone, and every report under `docs/` is a literate script. This item's remaining `Open` bullets (site publishing integration, Markdown figure output, PDF Chromium, theme toggle, cache keying) still stand as real work; only the premise — choosing between Marimo and a lighter alternative — is settled.
